# IT Help Desk Escalation Process

## Purpose

This document defines a structured escalation process for IT support issues that cannot be resolved at the initial support level.

Escalation ensures that unresolved technical issues are directed to the appropriate team with sufficient information for further investigation.

## 1. When to Escalate

An issue should be escalated when:

- The issue cannot be resolved using standard troubleshooting procedures.
- The issue requires administrator privileges or specialized access.
- Multiple users are affected.
- A critical business application is unavailable.
- A suspected security incident is identified.
- Hardware failure is suspected.
- The issue continues after troubleshooting.
- The issue exceeds the support technician's knowledge or authorization.

## 2. Escalation Levels

### Level 1 – Help Desk Support

Responsibilities:

- Receive and document user issues.
- Perform basic troubleshooting.
- Resolve common software, connectivity, and account issues.
- Verify resolution with the user.
- Escalate unresolved issues.

Examples:

- Password reset requests.
- Basic Wi-Fi connectivity problems.
- Printer connection issues.
- Outlook troubleshooting.
- Basic application support.

### Level 2 – Technical Support / Senior IT Support

Responsibilities:

- Investigate complex technical issues.
- Perform advanced troubleshooting.
- Analyze system logs.
- Investigate network, operating system, and application problems.
- Support Level 1 technicians.

Examples:

- Persistent network connectivity issues.
- Complex application failures.
- Operating system errors.
- Driver and configuration problems.
- Repeated system performance issues.

### Level 3 – Specialized IT Teams

Responsibilities:

- Investigate infrastructure-level problems.
- Resolve complex technical failures.
- Perform specialized configuration and system changes.
- Handle security-related investigations.
- Provide expert support.

Examples:

- Server outages.
- Network infrastructure failures.
- Suspected security incidents.
- Enterprise application failures.
- Advanced hardware problems.

## 3. Escalation Workflow

1. Record the reported issue.
2. Assess impact and urgency.
3. Perform initial troubleshooting.
4. Review the troubleshooting results.
5. Determine whether escalation is required.
6. Identify the appropriate support team.
7. Prepare escalation details.
8. Transfer or assign the issue.
9. Inform the user about the escalation.
10. Track progress until resolution.
11. Document the final outcome.

## 4. Information Required for Escalation

Include the following information:

- Ticket or incident number.
- User name and contact details.
- Device name or asset ID, if available.
- Date and time the issue occurred.
- Issue description.
- Error messages.
- Business impact.
- Number of affected users.
- Troubleshooting steps performed.
- Results of each troubleshooting step.
- Screenshots or relevant logs.
- Reason for escalation.
- Current status.

## 5. Priority Assessment

### High Priority

Examples:

- Multiple users unable to access a critical service.
- Major business application outage.
- Suspected security incident.
- Critical system unavailable.

Action:
Notify the appropriate support team promptly and follow organizational incident procedures.

### Medium Priority

Examples:

- A single user unable to access an important application.
- Repeated connectivity issues.
- A system experiencing significant performance problems.

Action:
Perform troubleshooting and escalate if the issue cannot be resolved within the support team's scope.

### Low Priority

Examples:

- Minor application issues.
- Non-critical peripheral problems.
- General software assistance.

Action:
Follow standard support procedures and escalate if necessary.

> Priority must be determined using the organization's incident management policy. These examples are for educational reference.

## 7. User Communication

When escalating an issue:

- Explain that further investigation is required.
- Provide a clear status update.
- Avoid promising an exact resolution time unless confirmed.
- Inform the user when additional information is needed.
- Keep the user updated according to support procedures.

## 8. Closure

Before closing the issue:

- Confirm the solution has been implemented.
- Verify functionality.
- Obtain user confirmation when possible.
- Document the resolution.
- Record any preventive recommendations.
- Close the ticket according to organizational procedures.
